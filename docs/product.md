# 방향·도메인·첫 MVP

현재 대화에서 합의한 내용을 요약한다. TypeScript·pnpm·Node.js, Next.js·React, Turborepo를 채택했다. 구체적인 도구 버전과 세부 상호작용은 미정이다.

## 방향

na는 나의 확장이다. 자기 이해는 별도 분석 모듈로 확정하지 않는다. 데이터·파이프라인·도구 선택의 주권성을 중시하며, 정리와 메타데이터 부담을 줄여 읽기·생각·대화에 에너지를 쓸 수 있게 한다. 포착은 정리되지 않아도 유효하며 실패는 댓글·수정·참조를 통해 보완할 재료다.

## 용어

| 용어 | 의미 |
| --- | --- |
| Daily log | 사람이 하루 동안 남긴 기록을 모아보는 단위 |
| Block | 피드에서 시각적으로 구분되는 독립 작성 단위. 제목을 요구하지 않음 |
| Bullet | Block 안에서 빠르게 남기는 항목. 생각·질문·사건·할 일 등이 섞일 수 있음 |
| Feed / Timeline | 기록을 시간 흐름에 따라 보여주는 방식 |
| Calendar widget | 날짜를 골라 하루의 기록으로 돌아가는 진입점 |

Block은 일정 구간 자체가 아니다. 일정·활동과 연계한 자동 생성은 미래 기능이다. 위 관계는 경험 모델이며 파일 구조나 DB 스키마가 아니다.

수동 작성·자동 관측·도구 생성은 구별한다. 사람의 기록을 일괄적으로 '사고 기록'으로 분류하지 않는다.

## 첫 MVP

Memos와 유사한 제목 없는 Block 피드와 날짜 탐색에 Bullet Journal 방식의 수동 기록을 결합한다. Bullet Journal은 할 일 관리만을 뜻하지 않는다.

- 날짜를 선택하여 하루의 Feed를 연다.
- 제목 없이 Block을 만들고 Bullet을 빠르게 남긴다.
- 저장한 기록을 다시 읽고 이어서 작성한다.
- 많은 기록과 긴 Block이 있는 화면의 가독성을 확인한다.

완료 확인: 제목·태그·분류 없이 작성 가능, Block 구분과 날짜 재방문 가능, 앱을 다시 열어도 저장 내용 유지, 일반 기록이 할 일 상태 입력에 종속되지 않음.

먼저 결정할 것: 사용 기기, 정확한 도구 버전, 저장·백업·내보내기, 실행·배포, 저장 동작, Bullet 편집·기호, 날짜·시각 기준, 검색 범위.

## 운영 조건

노트북에서 검증 후 상시 가동 집 서버의 Docker에서 운영하고 Tailscale로 기기에서 접속한다. 첫 MVP는 온라인 전용·개인 사용자이며 다중 계정과 공유는 미래 고려 사항이다. 서버의 영속 데이터가 원본이고 클라이언트 캐시·오프라인 동기화는 후속 범위다. 파일 기반과 SQL 기반 저장 중 무엇을 쓸지는 아직 결정하지 않았다.

## 미래 탐색

Card/Zettel의 이름과 형태는 미정이다. 손필기·원자료 위의 메모·정리 뷰·출판용 텍스트를 독립적인 텍스트 Card로 단정하지 않는다. 템플릿·노하우·오답노트·ADR 등 실행 자원과 지식 자원의 관계도 조사한다.

시간·행동·프로젝트·책임의 외재화, 자동 활동 로그, 카드화 보조, 일정 연동, 미디어 뷰, 외부 자료 오버레이, 링크 복구와 접근 후보, 공유·출판은 첫 MVP 밖이다. 내부 기록 재방문과 외부 자료 이용 흔적은 구별한다. 원문 복구와 대체 지식 탐색도 다른 결과다.
