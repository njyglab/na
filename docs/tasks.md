# 후속 과제

상태 기준: 2026-09-22. 아래 개발 기반 검증은 모두 미착수다. 사용자는 이를 후속 과제로 남기고 다음 세션에서 연구·사례 분석을 통한 도메인 모델링과 데이터 모델링을 우선하기로 했다.

## 개발 기반 검증 — 보류

- [ ] **1. pnpm workspace·Turborepo와 최소 Next.js 앱 구성**
  - 완료 기준: 도구 버전과 lockfile을 고정하고 `apps/web`을 로컬에서 실행할 수 있다. 설정과 실행 방법을 문서화한다.
- [ ] **2. 타입 검사·코드 검사·빌드 명령 통일**
  - 완료 기준: 패키지별 실제 작업과 루트의 Turbo 진입점을 연결하고 실제 실행이 통과한다. 없는 테스트를 통과시키는 빈 명령은 만들지 않는다.
- [ ] **3. GitHub Actions 검증 흐름 구성**
  - 완료 기준: 깨끗한 runner에서 lockfile 기반 설치·검사·빌드가 통과한다. YAML 작성만으로 완료 처리하지 않는다.
- [ ] **4. Docker 이미지 제작과 노트북 기동 검증**
  - 완료 기준: `linux/amd64` 이미지가 빌드되고 노트북에서 기동·접속을 확인한다. 앱 기능과 영속성 검증 범위는 당시 구현 수준에 맞춰 기록한다.
- [ ] **5. GHCR 게시 후 집 서버에서 동일 이미지 실행**
  - 완료 기준: 공개 이미지의 익명 pull, 서버 Compose 준비, 동일 digest 실행, Tailscale 경유 접속을 확인한다. 실제 결과와 이미지 식별자를 남긴다.

실행 계획은 [SDLC 기준안](sdlc.md)을 따른다. 현재 앱·workspace 설정·CI·Dockerfile·Compose는 아직 없고 GHCR 게시나 집 서버 검증도 하지 않았다.

이 과제를 완료하기 전에 도메인·데이터 연구를 진행해도 된다. 자동 실행·예약 작업은 아니다.
