# Roam Research: 백서의 구상과 현재의 방향

조사: 2026-09-28, Codex. 범위: 공식 백서·도움말·변경 이력·공개 `roam-tools` 저장소. 현재 방향은 공개된 기능과 변경에서 도출한 해석이며 회사의 비공개 로드맵이 아니다. 로그인·설치·개인 그래프 편집·AI 연결은 수행하지 않았다. [사례·주장 장부](../cases/roam.md), [이전 루만 비교](luhmann-note-system.md).

## 1. 이번 조사의 결론

Roam을 ‘루만식 노트에 backlink를 붙인 앱’으로만 이해하면 출발점과 최근 변화를 모두 놓친다. 백서는 **자연어로 된 생각을 작은 단위로 재사용하고, 서로 다른 판단을 보존하며 협업하는 환경**을 구상했다. 현재 공개 자료에서는 그중 블록·참조·문맥의 재사용을 바탕으로, 읽기와 포착, 검색, AI의 그래프 접근을 확장하는 방향이 뚜렷하다. [S01–S09; 해석]

반면 백서의 베이지안 추론, 논증 평가, 예측시장을 현재의 완성된 기본 기능으로 소개해서는 안 된다. 백서에 추가된 「About this Paper」는 이 기능들의 우선순위가 낮아졌으며 중요한 사용 사례를 지나치게 복잡하게 만들 위험이 있었다고 직접 설명한다. 후기가 언제 추가되었는지는 확인하지 않았다. [S01]

현재 방향은 네 축으로 요약할 수 있다.

1. **블록과 참조의 작업 환경을 다듬기:** 검색 미리보기, 문맥 경로, 표 편집, 문서 모드, 모바일 개선.
2. **외부 자료를 읽는 자리와 노트 연결하기:** Roam Reader와 PDF 관련 작업.
3. **문자 일치 검색을 의미 검색으로 확장하기:** 기존 키워드 결과와 의미 유사도 결과를 함께 사용.
4. **AI가 노트를 읽고 쓰는 통로 만들기:** 원격·로컬 MCP와 CLI, 권한, 작성 주체 표시, 사용자별 그래프 관행 안내.

이는 ‘사람이 생각하는 도구를 포기하고 AI 생성기로 전환했다’는 단정과 다르다. 최근 기록에는 사람이 직접 읽고 쓰는 인터페이스의 개선도 계속 나타난다. 또한 AI 연결이 있다는 사실만으로 백서의 집단적 추론 체계가 실현된 것은 아니다. [S04–S09; 해석]

## 2. Roam 자체를 먼저 이해하기

### 중심 단위는 페이지와 블록, 그리고 그 문맥이다

페이지는 이름을 가진 진입점이고, 그 안의 블록들은 아웃라인으로 조직된다. 다른 페이지나 특정 블록을 참조하면 내용을 다른 문제에서 다시 만날 수 있다. 태그도 별개의 분류 체계라기보다 표시 방식이 다른 페이지 참조다. [S02–S03]

중요한 차이는 ‘같은 글을 여러 곳에 붙이기’ 안에도 서로 다른 동작이 있다는 것이다.

| 동작 | 유지되는 관계 | 사고·집필에서의 의미 |
|---|---|---|
| 페이지 링크 | 이름 붙은 페이지로 이동 | 주제·인물·문제의 진입점 |
| 블록 참조 | 특정 블록의 동일성을 유지해 다른 곳에서 표시 | 같은 문장을 여러 논의에서 사용 |
| 블록 임베드 | 원본을 다른 문맥에서 보여 주고 편집 연결 | 원래 내용을 다른 작업면에서 다루기 |
| 텍스트로 대체 | 독립적인 복사본 | 원문과 별도로 고칠 수 있으나 연결은 끊어짐 |
| 별칭 | 다른 표현으로 원본을 가리킴 | 본문 문장과 참조 대상의 표현을 분리 |
| `text and alias` | 수정 가능한 복사본과 원본 링크 | 자기 초안으로 바꾸면서 출처 경로 유지 |

공식 Block References 문서의 설명을 요약했다. 이번에는 이 동작을 실제 그래프에 써서 검증하지 않았다. 참조된 텍스트가 갱신된다는 사실은 그 문장을 사용한 모든 논증이 자동으로 수정·검증된다는 뜻이 아니다. [S02; 해석]

### 공개 help 그래프에서 실제로 본 경험

공식 도움말은 일반 문서 사이트와 달리 그 자체가 Roam 그래프다. 백서와 기능 설명 아래에는 이를 참조한 다른 페이지의 블록과 상위 문맥이 모여 있었다. 백서의 접힌 하위 절을 펼쳐 읽었고, 페이지별 Linked References를 확인했다. [O01]

이 경험은 ‘문서 하나를 읽는다’에서 ‘이 내용을 다른 곳에서는 어떻게 사용했는가를 본다’로 자연스럽게 이어진다. 다만 모든 backlink가 잘 선별된 읽기 경로인 것은 아니다. 변경 이력이나 같은 자료의 반복 참조도 섞인다. 참조의 존재와 읽을 가치의 판단을 구별해야 한다. [O01; 해석]

## 3. 백서는 무엇을 제안했는가

### 작성 시기와 읽는 법

공식 페이지는 백서가 **2017/2018년 겨울**에 작성되었다고 밝힌다. 창업자로 Conor White-Sullivan과 Joshua Brown을 소개하고, Richard Meadows가 공동 집필했다고 설명한다. 이 문서는 제품의 초기 비전과 문제 설정을 읽는 일차 자료다. 현재 기능 명세나 성과 검증 논문은 아니다. [S01, About Roam / About this Paper]

본문에는 구현을 묘사하는 현재형과 미래 구상이 섞여 있다. 따라서 다음 세 층을 분리했다.

- **문제 진단:** 파일 분류, 복사 중복, 맥락 분리 때문에 사고와 협업이 어렵다는 주장.
- **표현·상호작용 제안:** 작은 단위를 여러 맥락에서 재사용하고 관계를 드러내는 방식.
- **강한 미래 비전:** 확률·신뢰도·집단 평가를 통해 판단을 갱신하는 지식 체계.

### 장별 논지

| 위치 | 핵심 제안 | 분석할 때 남는 질문 |
|---|---|---|
| §1–3 문제 설정 | 정보 증가와 인간 판단의 한계, 파일 캐비닛식 조직의 중복·맥락 손실 | 모든 파일 기반 도구가 같은 제약을 갖는가? |
| §4 지식 그래프 | 한 단위를 겹치는 여러 배열에서 재사용하고 갱신 | 동일 내용과 별도 해석은 언제 갈라야 하는가? |
| §5 논증 의존성 | 결론이 어떤 전제·근거에 기대는지 명시하고 용어의 모호성을 줄임 | 링크가 실제 지지·반박 관계를 충분히 표현하는가? |
| §6.1 비선형 인과 | 단선적 설명 대신 상호작용·피드백을 표현 | 그림의 연결이 인과를 입증하는가? |
| §6.2 베이지안 추론 | 근거 변화가 신뢰도와 의사결정 평가에 반영되는 체계 | 확률·독립성·모델 가정을 누가 정하고 검증하는가? |
| §7 우연한 발견 | 좁은 재검색과 넓은 탐색을 조절해 뜻밖의 연결을 만남 | 관련성과 새로움, 잡음을 어떻게 평가하는가? |
| §8 협업 | 강제된 단일 합의 없이 서로의 지식·전제를 재사용 | 이견을 남기면서 변경·책임·평가를 어떻게 유지하는가? |

위 표의 마지막 열은 연구자의 질문이며 백서의 검증 결과가 아니다. §6과 §8의 접혀 있던 하위 절도 열어 읽었다. [S01; O01]

### 백서에서 특히 중요한 세 가지

**첫째, 파일 트리의 대안은 ‘그래프 그림’보다 재사용 가능한 내용 단위다.** 백서는 같은 단위를 여러 순서와 계층에서 쓰고, 연결된 곳에 변경이 반영되며, 필요하면 별도 갈래로 발전시키는 것을 강조한다. 이 질문은 블록 참조와 복사·변형을 구별하는 현재 상호작용에서도 살아 있다. [S01 §4; S02]

**둘째, 자연어 협업에도 코드처럼 구성 가능한 도구가 필요하다는 발상이다.** §8.3은 공동 지식이 하나의 최종 문서에 합의해야 하는 상태를 비판하며, 서로의 결과를 구성 요소로 삼는 코드 협업과 비교한다. 이를 곧바로 ‘현재 Roam에 자연어 Git이 구현되었다’고 읽을 수는 없다. 공유 편집, 참조 재사용, 주장 계보, 독립적인 견해의 병합은 서로 다른 역량이다. [S01 §8.2–8.4; 해석]

**셋째, 지식을 저장하는 문제에서 지식을 평가하는 문제까지 나아가려 했다.** 백서는 다수의 판단, 신뢰성 점수, 예측시장 등 평가 방식을 탐색한다. 핵심은 링크 개수가 아니라 무엇을 믿을지의 판단이다. 이 부분은 초기 포부를 이해하는 데 중요하지만 후기가 명시한 우선순위 조정을 함께 읽어야 한다. [S01 §8.4, About this Paper]

### 백서에 동의하지 않아도 되는 부분

파일 저장 방식과 화면의 조직 방식은 같은 층위가 아니다. 파일에 저장해도 링크·임베드·여러 뷰를 제공할 수 있다. 백서의 파일 캐비닛 비판은 문제를 선명하게 만드는 수사이지만, 모든 파일 기반 시스템의 불가능성을 증명하지 않는다. Obsidian 비교에서 확인한 기능도 이 일반화의 반례다. [이전 비교](luhmann-note-system.md#6-obsidian은-외형만-재현하는가)

뇌·신경망과의 비유도 인터페이스가 인지적으로 우수하다는 증거는 아니다. 백서에 나오는 정보량·뇌 용량·에너지 수치는 이번 연구에서 독립 검증하지 않았으며 제품 선택의 근거로 사용하지 않는다. [S01 §1–3; 연구 범위]

또한 일반적인 링크 그래프, 논증의 의존성 그래프, 확률 모형은 다르다. 관계에 가중치를 붙였다고 올바른 베이지안 추론이 저절로 성립하는 것은 아니다. 같은 원천을 반복 인용한 두 문장을 독립된 증거 두 개로 계산할 수 있는지부터 판단해야 한다. **표현 가능성, 계산 가능성, 판단의 타당성**을 구별하는 것이 백서를 생산적으로 읽는 방법이다. [연구 해석]

## 4. 원래 비전과 현재 기능은 어디까지 연결되는가

| 백서의 방향 | 현재 확인한 대응 | 판정과 경계 |
|---|---|---|
| 작은 단위의 재사용 | 블록 참조·임베드·별칭·독립 복사 | 공식 기능 설명 확인. 모든 파생 주장 갱신은 아님 |
| 여러 문맥 사이의 이동 | Linked References, 원래 위치·사이드바 열기, 검색 결과의 경로·미리보기 | 일부 공개 UI 직접 관찰, 나머지는 문서 확인 |
| 우연한 재발견 | 의미 검색, 링크 제안, Related Notes 확장 | 가능 조건이 늘어남. 창의성 개선은 미검증 |
| 명시적 논증·확률 갱신 | 후기에서 우선순위 하향 명시 | 현재 기본 기능으로 완성되었다는 증거 없음 |
| 공동 지식 구성 | 공유 그래프를 전제로 한 권한·작성 주체 기능 | 백서의 다원적 지식 재조합 전체가 구현됐다는 증거는 아님 |
| 신뢰성 점수·예측시장 | 초기 구상과 후기의 설명 | 현재 제품 기능으로 보고하지 않음 |
| 사고 지원의 확장 | AI가 검색·읽기·포착·초안·그래프 편집을 수행할 통로 | 백서의 결정론적/확률적 평가 체계와 LLM은 구별해야 함 |

‘확인되지 않음’은 모든 플러그인이나 개인 구현에도 존재하지 않는다는 선언이 아니다. 이번에 읽은 공식 자료가 어디까지 뒷받침하는지의 경계다. [S01–S09]

## 5. 현재 방향: 사람의 읽기와 쓰기를 계속 다듬는다

### 구조가 필요해지는 시점까지 포착을 가볍게 유지

Roam Reader는 웹 원문의 레이아웃을 유지한 채 옆에서 하이라이트·태그·댓글을 적는 Chrome 확장이다. 공식 설명에 따르면 읽을 자료를 저장하면 먼저 읽기 목록의 블록이 되고, 실제로 노트를 적기 시작할 때 자료별 페이지로 확장된다. 하이라이트는 원문 순서대로 들어가며 중첩을 이용해 읽는 동안 아웃라인을 만들 수 있다. [S09]

여기서 주목할 것은 저장한 모든 URL에 즉시 완성된 문서를 만들지 않는다는 점이다. 포착과 깊은 읽기를 다른 단계로 취급한다. 다만 웹페이지가 바뀌었을 때의 하이라이트 복원, 원문 보존, 인용 판본 고정은 이번에 시험하지 않았다. ‘원문과 함께 읽기’가 곧 영구 보존을 뜻하지 않는다. [해석·미확인]

## 6. 현재 방향: 의미 검색과 AI의 그래프 접근

### 의미 검색은 이미 적은 말과 지금 찾는 말 사이를 잇는다

공식 의미 검색 설명은 아웃라인 일부에 페이지 제목과 상위 블록의 문맥을 포함해 임베딩을 만들고, 변경된 부분을 다시 색인한다고 한다. 검색 시 의미 유사도와 키워드 결과를 함께 사용한다. 이는 사용자가 예전 표현을 정확히 기억하지 않아도 관련 내용을 찾게 하는 기능이다. [S05]

기본 제공 경로는 Voyage AI를 이용하며, 사용자 지정 경로는 원격 호환 API나 로컬 모델 서버를 선택할 수 있다. 원격 API와 로컬 엔드포인트는 데이터가 지나는 경로가 다르다. 문서는 암호화된 그래프도 임베딩 계산에는 평문이 필요하다고 설명한다. 따라서 ‘그래프 암호화’, ‘로컬 연결’, ‘AI 처리 위치’는 같은 설정이 아니다. 이 조사는 기능 문서의 설명을 확인한 것이며 데이터 흐름을 직접 계측하지 않았다. [S05]

의미 유사도는 지지·반박·인과 관계가 아니다. 검색 결과가 가까워도 서로 모순되거나 같은 원문을 반복한 기록일 수 있다. 백서의 §7과 연결되는 재발견 수단으로 볼 수 있지만, §6의 확률 추론이 구현된 것으로 해석하면 안 된다. [해석]

### 원격 MCP, 로컬 MCP, CLI를 구별

MCP는 외부 AI가 Roam의 읽기·쓰기 도구를 호출하는 접점이다. 일반적인 AI 채팅창과 달리 실제 그래프의 페이지·블록을 다룬다. 다만 연결 방식마다 가능한 일이 다르다. [S06–S08]

| 방식 | 연결 경로 | 이번 자료에서 확인한 경계 |
|---|---|---|
| 원격 Roam MCP | AI 도구 → Roam의 호스팅 서비스 | 사용자 컴퓨터가 켜져 있지 않아도 연결. 선택한 그래프와 권한 범위로 접근 |
| 로컬 MCP | AI 도구 → 로컬 서버 → Roam Desktop | 데스크톱 앱 필요. 로컬·복호화된 그래프 접근과 데스크톱 기능을 다룰 수 있음 |
| Roam CLI | 터미널 명령 → 같은 로컬 도구 계층 | 셸에서 작업하는 도구에 제공하는 접점. 새 지식 모형이 따로 생기는 것은 아님 |

공식 원격 MCP 설명에서 암호화 그래프는 읽을 수 없고 제한된 추가 기록을 지원한다. 로컬 연결은 장치에서 복호화된 데이터를 다룬다. 공개 아키텍처 문서는 의미 검색·링크 제안·확장 도구 호출 등이 로컬 전용이며 호스팅 MCP와 기능 집합이 같지 않다고 구분한다. [S06, S08, S11]

**로컬 연결이라고 외부 AI 제공자에게도 내용이 전달되지 않는다는 뜻은 아니다.** 이 표현은 Roam에 접속하는 구간을 설명한다. 모델이 어디서 실행되는지, 어떤 문맥을 받는지는 별도 문제다. [경계에 대한 해석]

### ‘노트를 쓰는 주체’가 늘어나는 변화

공식 AI 작업 안내는 개인 그래프의 관행을 `roam/agent guidelines`에 적고, 연결별 권한과 작성 주체 표시를 사용한다고 설명한다. AI 연결을 통해 쓴 내용은 그 연결에 귀속되어 사람의 기록과 구별할 수 있다. 이는 사람이 생성한 내용과 도구가 생성한 내용을 분리하는 데 관련된 기능이다. [S07]

그러나 작성자가 표시된다는 것만으로 생성에 사용한 모든 근거·프롬프트·모델·판단 과정이 보존되지는 않는다. 문서가 안내하는 Graph History도 API의 모든 대량 작업을 간단히 되돌리는 보장으로 읽어서는 안 된다. `roam-tools` README는 API 변경과 삭제의 복구 한계를 별도로 명시한다. 복구 단위와 실제 보존 기간은 후속 실행 검증 대상으로 남긴다. [S07–S08; 해석]

이 지침은 AI를 사용하는 모든 Depot 확장에 동일하게 적용되는 약속도 아니다. 공식 안내 자체가 확장마다 규칙이 다르며 연결의 권한·귀속 보장을 그대로 적용할 수 없다고 구분한다. [S07]

### AI 연동의 변화도 버전별로 확인

공개 `roam-tools` 변경 이력에서 확인한 주요 지점은 다음과 같다. 이것은 Roam 전체 앱의 버전이 아닌 연결 도구의 버전이다. [S10]

- 2026-06-03, 0.7.0: daily note에 추가하는 도구.
- 2026-07-15, 0.9.0: 로컬 의미 검색 도구.
- 2026-07-20, 0.9.1: 링크 후보 제안. 제안 자체는 링크 생성과 구별됨.
- 2026-07-29, 0.9.2: 실행 중인 확장이 등록한 AI 도구 호출.
- 2026-08-02, 0.10.0: 블록 참조와 잘린 검색 결과를 잘못 덮어쓰지 않게 하는 읽기·쓰기 형식 안내.
- 2026-08-26, 0.11.0: 삭제 대상이 없었던 경우를 실패로 보고하는 동작 등.

이 목록은 단순히 ‘AI 기능 수가 늘었다’보다, AI가 구조를 훼손하지 않고 그래프를 다루게 하는 계약이 발전하고 있음을 보여 준다. 다만 문서상의 수정이 실사용에서 어느 정도 오류를 줄였는지는 측정하지 않았다. [해석]

## 7. 확장 생태계를 기본 제품과 섞지 않기

공식 Change Log에는 Roam Depot Extensions 항목이 함께 있다. 여기에 등장했다고 모두 Roam 팀이 만든 기본 기능이거나 누구에게나 즉시 제공되는 것은 아니다. [S04]

| 예 | 확인한 내용 | 해석 범위 |
|---|---|---|
| Related Notes, 2026-07-13 항목 | Roam의 의미 검색을 활용해 관련 기록을 보여 주는 확장 | 기본 검색 역량 위에 자동 재노출 경험을 더하는 예 |
| Roam Grid, 2026-08-22 항목 | 중첩 블록인 표를 유지하며 스프레드시트식 기능을 제공한다는 설명 | 같은 데이터 위의 새로운 작업면. 실제 보존성은 미검증 |
| RoamPrompt, 2026-09-11 항목 | 외부 제작자가 원자료 기반 노트·검토할 후보 노트 생성을 소개 | 기본 AI 기능으로 취급하지 않음. 열람 본문에는 아직 Depot 미등재라고 명시됨 |

따라서 현재 방향을 해석할 때 **핵심 제품, 공식 별도 통합, 제3자 확장, 소개·검토 중인 구현**을 분리해야 한다. 특히 RoamPrompt처럼 목록 제목과 본문 배포 상태가 다를 때는 본문의 제한을 함께 남긴다. 이번에는 이 확장들의 설치·효과·보안 검증을 수행하지 않았다. [S04]

## 8. 루만에서 무엇이 이어지고 무엇이 달라졌는가

루만의 카드 번호와 Roam 블록 주소는 모두 다시 찾아가고 참조할 대상을 만든다. 그러나 루만의 선택적인 진입 색인과 Roam의 자동 backlink, 의미 검색, AI의 검색은 서로 다른 찾기 장치다. 연결을 고르는 일의 일부가 작성 시점에서 검색·검토 시점으로 옮겨간다. 근거: [이전 루만 조사](luhmann-note-system.md), S02–S08. 마지막 문장은 연구 해석이다.

Roam은 종이 한 장의 모양을 복제하기보다, 작은 내용을 여러 문맥에서 다루고 다른 작성 주체와 재사용하는 방향으로 나아간다. 이때 핵심 질문도 달라진다. ‘어디에 넣을까’뿐 아니라 **‘이것은 원본인가 복사인가, 지금 보이는 내용은 누가 바꿨는가, 이 연결은 사람이 썼는가 제안된 것인가’**가 중요해진다. [해석]

백서에서 루만을 모든 기능의 직접 기원으로 명시한 근거는 찾지 못했다. 반면 Engelbart, Nielsen, Lamport 등의 참고 문헌은 확인했다. 후대 Zettelkasten 활용과 제품 설계의 직접 계보는 계속 구별한다. [S01 Further Reading; 이전 조사]

## 9. na 연구의 현재 방향에 주는 시사점

이 절은 Roam의 제품 방향과 구별되는 **na 연구 가설**이다. 현재 MVP의 제목 없는 Block·수동 daily log를 바꾸거나 AI·그래프 구현을 채택하지 않는다.

| 연구 질문 | Roam이 제공한 구체적인 단서 | 검증할 것 |
|---|---|---|
| 포착과 조직은 언제 분리하는가? | Reader의 읽기 목록 블록 → 실제 주석 시 페이지 확장 | 나중에 구조화하는 방식이 누락과 유지 부담을 줄이는가 |
| 참조와 변형을 어떻게 구별하는가? | 참조·임베드·복사·별칭 | 원본 변경 뒤 인용과 자기 초안을 혼동하지 않는가 |
| 검색 결과에 얼마나 문맥을 보이는가? | 상위 경로·미리보기·backlink | 잘못된 항목 선택과 왕복 이동이 줄어드는가 |
| 도구가 쓴 기록은 어떻게 분리하는가? | 연결별 작성 주체와 권한 | 사람의 원문 보존, 도구 초안 검토·폐기를 지원하는가 |
| 연결을 누가 결정하는가? | 명시적 참조·링크 제안·의미 검색의 공존 | 제안을 사실 관계로 오인하지 않는가 |
| 표현을 바꿔도 내용의 정체성이 유지되는가? | 블록에 대한 여러 화면·외부 도구 접근 | 뷰 변경과 데이터 변경의 경계가 분명한가 |

현재 [Notion 중심 연구 방향](../notion-research-direction.md)의 ‘책임·연산·통제·재구성’ 관점으로는, Roam이 **내용의 주소화와 재사용, 문맥의 재노출, 외부 주체의 읽기·쓰기**를 분해해 볼 좋은 사례가 된다. DB 종류나 UI 형태를 그대로 채택하기보다 이 책임들의 경계를 연구하는 편이 적절하다. [연구 해석]

후속 실험은 가상 자료 몇 개로 좁힐 수 있다. 동일한 원문을 참조와 수정본으로 사용하고, 원문 변경 후 혼동을 검사한다. 표현이 다른 예전 메모를 키워드·의미 검색으로 찾아 결과의 누락과 오연결을 비교한다. AI는 원문을 직접 고치기보다 댓글·새 초안으로 제안하는 조건과 비교한다. 이것들은 제안이며 이번에 실행하지 않았다.

## 10. 조사 한계와 출처

가격·이용자 수·사업 성과·시장 점유율은 조사하지 않았다. 공식 문서가 기능을 설명한다는 것과 안정적으로 실행된다는 것, 인간의 사고 성과가 개선된다는 것은 구별한다. 날짜가 없는 도움말의 최초 출시일을 추정하지 않았고, 공개 저장소의 버전과 호스팅 서버의 실제 배포 버전을 동일시하지 않았다.
