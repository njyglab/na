# 다음 세션 — Darwin·Luhmann의 실제 PKM 인스턴스 탐구

작성: 2026-09-24. 상태: 다음 대화의 방향과 진행 방식 인수인계. 역사 자료의 본조사는 아직 하지 않았다.

## 사용자가 정한 방향

Darwin과 Luhmann은 실제로 사용한 기록 체계의 인스턴스를 대상으로 살펴볼 수 있다는 점에서 독특한 사례다. 다음 세션에서는 사용자가 실제 인스턴스에 대해 궁금한 점을 짚어가며 더 깊은 인사이트를 얻는다.

따라서 다음 작업의 중심은 정해진 양식을 한꺼번에 채우는 것이 아니라, 구체적인 노트·카드·배치·참조 흔적을 함께 보고 질문과 관찰을 발전시키는 것이다. 무엇을 먼저 살펴볼지는 사용자의 질문으로 정한다. 두 사람의 전체 기록 시스템을 한 번에 설명하거나 동일한 방식으로 비교할 필요는 없다.

여기서 ‘PKM 인스턴스’는 연구를 위한 현대적 관점이다. 당사자가 PKM이라는 이름이나 오늘날의 개념으로 자신의 실천을 이해했다고 주장하지 않는다.

## 현재까지 한 일

- 연구 구조와 14개 사례 후보 목록을 마련했다. 미착수 항목은 파일 대신 목록으로 관리한다.
- Memos와 Bullet Journal의 공식 문서 기반 초기 사례 분석을 작성했다.
- 정리 비용·계보·인간 성과 질문과 S1/S5 비교 시나리오, 잠정 vocabulary·na 가설을 연결했다.
- 기존 연구 및 전달받은 인수인계 원본 커밋: `bed8101`.

제품 실행·사용자 실험·장기 효과 검증은 미수행이다. Memos 자료는 가변 main 기준이며 커밋 고정이 남아 있다. 이는 후속 과제지만 이번 역사 사례 탐구의 선행 조건은 아니다.

Darwin·Luhmann은 아직 자료군·시기·개별 기록을 확정하지 않았고, 사례 파일도 만들지 않았다. 앞선 대화에서 소개된 자료 경로를 실제 조사 완료로 취급하지 않는다.

## ‘실제 인스턴스’에서 구별할 것

| 대상 | 확인할 것 | 주의점 |
|---|---|---|
| 원래 기록물 | 노트·카드의 특정 위치, 필기·도식·배열·수정·참조 흔적 | 남은 표본이 전체 실천을 대표한다고 가정하지 않음 |
| 당사자 실천 | 어떤 계기로 작성·찾기·연결·수정·재사용했는가 | 흔적만으로 일상의 행동을 확정하지 않음 |
| 당사자의 설명 | 자신의 기록법에 관해 남긴 설명과 시기 | 설명된 이상과 실제 사용의 차이 가능 |
| 편집·아카이브 | 전사·번호 부여·재배열·검색·링크의 주체 | 현재 웹사이트의 기능을 당시 능력으로 소급하지 않음 |
| 후대 해석 | 연구자·현대 방법론이 부여한 개념 | 원자료 관찰과 명확히 분리 |

원자료 이미지, 전사, 번역, 연구자 요약은 다른 자료다. 판독·번역이 불확실하면 표시한다. 한 기록에서 다른 기록으로 이어지는 관계는 실제 표식인지, 편집자가 복원한 관계인지, 우리가 제안하는 관계인지 구별한다.

## 다음 대화의 진행 방식

1. 사용자가 이미 구체적 질문을 주었다면 그 질문부터 시작한다. 없다면 어느 인물·어떤 실제 모습이 궁금한지 짧게 묻는다. 긴 설문이나 고정된 조사 순서를 요구하지 않는다.
2. 질문에 맞는 자료군과 시기를 좁히고, 접근 가능한 실제 기록 한 개 또는 연결된 소수의 기록을 고른다.
3. 원자료 위치를 보여주며 무엇이 실제로 보이는지 설명한다. 가능한 경우 이미지·전사·직접 링크를 함께 제공한다. 접근 불가나 판독 한계를 숨기지 않는다.
4. 사용자 질문 → 관찰 → 잠정 해석 → 대안 설명 → 남은 질문 순서로 대화한다. 답을 얻은 뒤 관련 사례·횡단 질문에 필요한 만큼 기록한다.
5. 더 큰 결론에 필요하면 다른 기록·시기·학술 자료와 대조한다. 첫 표본에서 전체 시스템이나 성과를 일반화하지 않는다.

사용자가 탐구 방향을 정할 수 있도록 한 번에 다루는 기록과 질문을 작게 유지한다. 네 층 분석은 관찰을 정리하는 렌즈이며, 대화 중 모든 항목을 강제로 채우는 체크리스트가 아니다.

## 질문 출발점 후보 — 사용자가 선택·변경

- 실제 페이지나 카드에는 무엇이 함께 적혀 있는가? 어디서 하나의 기록이 끝나는가?
- 기록의 번호·날짜·물리적 위치는 누가 언제 부여했는가?
- 어떤 연결은 명시적으로 적혀 있고 어떤 연결은 독자가 추론하는가?
- 특정 기록을 다시 찾는 실제 진입점과 경로를 복원할 수 있는가?
- 발췌·관찰·개인 해석·의문·반박을 구별하는 흔적이 있는가?
- 수정·취소·추가 삽입은 어떻게 남는가? 이전 생각을 복원할 수 있는가?
- 한 기록이 다른 기록이나 저술로 이어졌다는 근거가 있는가?
- 체계에 맞지 않는 메모, 끊어진 참조, 미완료 기록은 무엇을 보여주는가?

이 질문들은 현재 확인된 특징의 목록이 아니다. Darwin은 특정 노트 자료군부터, Luhmann은 특정 카드와 그 주변 참조부터 범위를 좁히는 방안을 검토할 수 있다. 인물별 구체 대상은 원자료 접근성과 사용자 관심에 따라 정한다.

## 기록 위치와 최소 근거

첫 실제 조사 후 `cases/darwin.md` 또는 `cases/luhmann.md`를 생성한다. 분량이 커지면 사례별 폴더로 확장하되 처음부터 빈 파일을 만들지 않는다.

관찰 단위마다 다음을 남긴다.

- 사용자 질문과 조사 범위.
- 자료 식별자·권/페이지/카드 번호, URL·정확한 위치·열람일.
- 원자료/전사/번역/당사자 설명/후대 해석 중 무엇인지.
- 관찰된 사실, 짧은 필요한 인용, 연구자 해석과 대안 설명.
- 연결을 실제로 따라간 범위, 접근·판독 한계, 다음 질문.

사례를 넘는 질문은 questions에 연결하고, 공통 용어는 synthesis/vocabulary.md에서 수정한다. 전체 대화 전문을 옮길 필요는 없다. 확정된 사례 범위와 발견·미해결 질문을 보존하면 된다.

## 유지할 경계

사례 자체의 기술 → Knowledge → Knowledge System → Interaction → Human Outcome → na implications 순서를 유지한다. 현대 Zettelkasten의 atomic/permanent/structure note 규칙을 루만에게 자동 적용하지 않는다. 기록법을 인물의 성취에 대한 단일 원인으로 설명하지 않는다.

na의 Block/Bullet/Daily log를 원자료에 먼저 투영하지 않는다. 저장 방식·UI·AI 기능 결정, 설치·앱 생성은 이번 세션의 기본 작업이 아니다. 사용자 관심에서 나온 시사점은 근거와 반증 조건을 가진 가설로 남긴다.

## 새 대화에 전달할 시작 요청

> research/knowledge-systems/next-session-handoff.md를 읽고 Darwin·Luhmann 연구를 이어가자. 이번에는 실제 노트·카드와 그 연결을 PKM 인스턴스로 살펴보며 내가 궁금한 점을 함께 탐구하고 싶다. 먼저 내 질문에 맞는 자료를 좁혀 원자료를 보여주고, 실제 관찰과 해석을 구별해 설명해줘. 질문이 아직 없다면 어느 인물의 무엇부터 볼지 짧게 물어봐. 전체 사례 분석이나 na 설계를 미리 완성하기보다 구체적인 기록에서 질문과 인사이트를 발전시키고, 확인된 내용은 사례 문서와 관련 질문에 남겨줘.
